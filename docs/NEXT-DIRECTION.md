# 발전 제안 — The Anatomy of Scent

첨부한 GPT 대화의 최종 방향을 검토한 제안입니다. 이 문서는 다음 버전의 설계이며,
현재 실행되는 v1은 향 지도와 표현 비교 프로토타입입니다. 아래 경험은 아직 구현하지 않았습니다.

## 중심 경험

**하나의 향 설명을 세 관점으로 읽고, 한 가지 차이를 직접 확인한다.**

Notes / Feel / Family 관점 전환을 중심으로 삼습니다. 조합 게임의 완성·점수·레벨은 필요하지 않습니다.
첫 화면의 질문은 “같은 장미인데, 어떤 차이를 보면 마른 느낌과 매끈한 느낌을 구별할 수 있을까?”입니다.
이 질문이 추상적 비주얼의 의미와 사용자가 해야 할 행동을 함께 설명합니다.

## 대표 사례

두 개의 미리 준비한 교육용 설명 사례만 사용합니다.

| 관점 | 사례 A | 사례 B | 배우는 것 |
| --- | --- | --- | --- |
| Notes | Rose + Cedarwood | Rose + Sandalwood | 구체적인 노트와 바뀐 대상 |
| Feel | 마른 결에 주목하는 묘사 | 둥글고 매끈한 질감에 주목하는 묘사 | Dry / Creamy가 질감의 표현이라는 점 |
| Family | Floral과 Woody 방향을 함께 읽기 | Floral과 Woody 방향을 함께 읽기 | 큰 방향은 비슷해도 질감 설명은 달라질 수 있음 |

이 표는 노트만으로 실제 향수의 인상을 예측한 결과가 아닙니다.
대표적인 용례를 바탕으로 미리 작성한 두 장면을 읽는 비교입니다.
노트 이름·배합량·상호작용만으로 향을 계산할 수 있는 기능으로 소개하지 않습니다.

## 첫 30초의 흐름

1. 장미를 연상시키는 중심 형태와 나무 결을 연상시키는 지지 형태가 겹친 한 장면을 만납니다.
2. “무엇을 떠올리나요?”를 선택하면 Rose / Cedarwood 노트 이름이 해당 위치에 드러납니다.
3. “어떻게 느껴지나요?”로 바꾸면 대상 이름보다 꽃잎의 인상 / 마른 결 같은 묘사가 부각됩니다.
4. Cedarwood ↔ Sandalwood 비교를 전환하면 장미의 위치와 형태는 유지되고 나무와 관련된 질감만 바뀝니다.
5. 하단의 짧은 문장이 공통점, 달라진 요소, 주목할 차이를 정리합니다.
6. 관심 있는 단어를 선택하면 기존 관계 지도에서 같은 연결을 확인합니다.

관점은 세 단계의 미션이 아니라 자유롭게 왕복할 수 있는 렌즈입니다.
전문 용어 아래에 쉬운 질문을 함께 적어 무엇을 눌러야 할지 알려줍니다.

## 탭 이상의 관점 전환

동일한 장면을 유지하며 **강조의 단위**가 바뀌어야 합니다.

- Notes: 구체적인 향의 대상을 가리키는 지점과 노트 이름.
- Feel: 여러 대상을 가로지를 수 있는 질감의 영역과 표현. 하나의 노트와 하나의 질감을 고정 연결하지 않습니다.
- Family: 노트 하나보다 넓은 방향을 설명하는 묶음과 계열 이름. 실제 공식 계열 판정처럼 표시하지 않습니다.

선택한 사례와 탐색 대상은 관점 전환 후에도 유지합니다. 서로 다른 페이지를 보는 느낌을 피하고,
“지금 읽는 정보 종류가 달라졌구나”라는 이해가 남도록 합니다.
색만으로 구분하지 않고 유형 이름, 기호, 설명 문장을 함께 사용합니다.

## 시각적 임팩트의 역할

초기에는 겹쳐 보이던 형태가 선택 후 약간 분리되면서 정보의 구조가 드러납니다.
고정된 장미 중심과 바뀌는 나무 질감의 대비가 사용자의 행동을 보이게 합니다.
선택하지 않은 요소는 완전히 사라지지 않아 전체 맥락을 유지합니다.
계속 떠다니는 장식, 향수병에 재료를 붓는 동작, 정답을 맞히는 장치는 사용하지 않습니다.

사진·추상 비주얼은 감각의 비유입니다. 예쁜 이미지만 남지 않도록 항상
“무엇이 유지되었고, 무엇이 달라졌으며, 무엇에 주목하는가”라는 문장을 함께 보여줍니다.

## 현재 v1에서 유지 / 변경 / 보류

| 구분 | 작업 |
| --- | --- |
| 유지 | 세 정보 유형, 관계 설명, 선택 강조, What to Notice, 모바일·키보드 접근성 |
| 변경 | 첫 화면을 단어 지도에서 하나의 사례 관찰로 바꾸기 |
| 변경 | 지도는 관련 개념을 확인하는 후속 탐색으로 이동 |
| 변경 | 비교는 우선 미리 작성한 한 가지 사례 쌍에 집중 |
| 재검토 | 오각형의 편집된 수치. 현재는 실측값이 아님을 명시한 예시지만, 다음 버전에서는 설명 가능한 정성적 대비를 우선 사용 |
| 보류 | 자유 조합, 실제 조향 예측, 추천, 계열 자동 판정, 시간 변화 시뮬레이션 |

오각형이 꼭 필요하다면 검토할 콘텐츠와 축을 먼저 확정합니다. 모양을 채우기 위해 값을
만들지 않습니다. 비교의 중심은 두 이미지의 면적보다 공통점과 구별하는 문장입니다.

## 미드텀의 구현 범위

한 화면, 세 관점, 두 사례, 한 번의 변수 전환으로 충분합니다.
HTML/CSS는 관계와 전환을 표현하고, 작은 JavaScript 상태는 선택한 관점·사례·대상을 보존합니다.
모바일은 장면 → 관점 선택 → 설명 → 사례 비교 순서로 쌓습니다.
reduced motion에서는 분리 애니메이션 없이 같은 최종 정보가 즉시 나타납니다.

다음 설계 순서:

1. 두 사례의 설명과 노트 용례를 신뢰할 수 있는 출처로 검토합니다.
2. 같은 장면의 Notes / Feel / Family 세 상태와 노트 전환 전후를 와이어프레임으로 그립니다.
3. 무엇이 그대로 남고 무엇이 바뀌는지 명확한 대표 화면 하나를 구현합니다.
4. 처음 보는 사용자에게 Rose / Floral / Creamy가 서로 다른 정보인지 질문합니다.
5. “어떤 향인가?” 대신 “어떤 차이에 주목하면 되는가?”를 설명할 수 있는지 확인합니다.

프로젝트의 임팩트는 기능의 수보다, 처음에는 하나의 이미지였던 것이 탐색 후
읽을 수 있는 구조로 바뀌는 데서 나옵니다.
