# Week 05 — A Web That Responds

## 반응의 이유

이 프로젝트에서 선택 반응은 사용자가 관찰할 대상을 알아보기 위한 장치입니다.
한 요소를 선택하면 그 부분은 남고 다른 부분이 물러납니다. 관점을 전환하면 같은 사례에서
읽는 정보의 종류가 바뀝니다. 효과 자체보다 선택 전후에 무엇을 이해할 수 있는지에 주목했습니다.

## 공간과 정보

처음 관계 지도에서는 단어의 위치와 연결선만으로 관계를 충분히 이해하기 어려웠습니다.
그래서 모든 연결에 이유를 적고, 다음 디자인에서는 하나의 구체적인 사례를 먼저 관찰하도록 했습니다.
Notes·Feel·Family가 서로 다른 질문에 답한다는 점을 같은 장면의 강조 단위로 보여줍니다.

## 좁은 화면에서 배운 점

지도나 장면을 그대로 작게 줄이는 것보다, 읽는 순서에 맞게 장면 아래에 설명을 배치하는 것이
더 명확했습니다. 제출용 프로토타입은 약 680px에서 한 열로 바뀌고, 비교의 공통점·변경점·관찰 단서를
세로로 쌓습니다. 관점·사례·집중 상태는 화면 폭과 관계없이 유지합니다.

## 상태와 접근성

hover는 상호작용 가능성을 알려주지만 필수 설명을 숨기지 않습니다. 세 관점은 방향키·Home·End로
전환할 수 있고, 요소 선택과 사례 비교는 native button으로 조작합니다. 선택 상태를 텍스트·기호·배경과
ARIA로 함께 표시합니다. 움직임 감소 설정에서는 전환 없이 같은 최종 정보를 제공합니다.

## 실제 검증 결과

- 기존 웹사이트: 빌드 성공, Playwright 브라우저 테스트 11개 통과.
- 제출용 디자인 프로토타입: 21개 기능·레이아웃 점검 통과.
- Notes→Feel→Family 전환과 사례 변경에서 선택 상태 유지 확인.
- 키보드 탭 이동, 방향키 전환, 집중 해제 확인.
- 320 / 390 / 680 / 681 / 768 / 1024 / 1440px에서 가로 넘침 없음.
- 런타임 JavaScript 오류 없음, reduced motion에서 전환 없음.
- 슬라이드: 21장 출력, 텍스트 영역 넘침 없음, 한글 표시 확인.

이 결과는 기능과 표시의 검증입니다. 사용자의 향 이해가 실제로 개선되는지와 콘텐츠의 전문적 정확성은
발표 피드백과 후속 사용자·전문가 검토에서 확인해야 합니다.
