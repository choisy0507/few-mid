# Week 05 — A Web That Responds

## 선택의 이유

8개 계열을 모두 같은 첫 구조로 보여주되, 선택한 계열 주변의 노트와 표현은 필요할 때 펼칩니다.
다른 7계열이 남아 있으면 세부 정보를 읽는 동안에도 전체 위치를 파악할 수 있다는 디자인 가설입니다.
비교는 개념 안에서 열고 닫을 때 같은 지도 상태와 호출 버튼의 초점을 유지합니다.

## 데이터와 화면을 다르게 조직

다섯 유형을 그대로 다섯 메뉴로 만들지 않았습니다. 지도에는 Family·Note·Descriptor를 중심으로,
Accord·Material은 설명에 필요할 때 공개합니다. 특징을 단일 하위 분류로 넣지 않고 관계로 저장합니다.
관계선에도 관련 노트, 드러날 수 있는 특징, 교육용 비교 등의 의미와 이유를 함께 적었습니다.

## 실제 반응형 문제

768px에서 지도 양쪽의 보조 계열과 주변 노드가 약 6px 겹치는 것을 측정했습니다.
해당 중간 폭에서 노드의 최소 너비와 글자 크기·여백을 조정하고 다시 검증했습니다.
1050px 이하에서는 상세 패널을 아래로, 760px 이하에서는 전체 계열과 펼친 개념을 각각 선택 블록으로 구성합니다.
좁은 화면에서도 다른 계열과 현재 관심의 맥락은 유지합니다.

## 인터랙션과 접근성

계열 버튼을 유지하면서 선택 위치로 이동하게 하고, 주변 개념은 펼침으로 드러납니다.
hover는 조작 가능성을 알려주고 필수 정보는 클릭·터치·키보드로 읽습니다.
움직임 감소 설정에서는 위치 변화와 정보에 즉시 도달할 수 있습니다.
색뿐 아니라 기호, 유형 이름, 테두리, 선택 상태로 관심을 표시합니다.

## 검증 결과

- 프로덕션 빌드 성공, 실제 브라우저 테스트 15개 통과.
- 전체 8계열과 모든 계열의 펼침, 노트와 다중 특징 확인.
- Material·Accord는 상세에만 공개, Musk와 Musky는 별도 유형.
- 개념 내부 비교, 같은 대상 선택 안내, 닫기와 초점 복귀 확인.
- 320 / 390 / 768 / 1024 / 1440px에서 넘침과 노드 겹침 없음.
- 런타임 오류 없음, 키보드 조작과 움직임 감소 확인.
- 단일 HTML 프로토타입의 탐색·비교·외부 런타임 요청 없음 확인.

기능과 레이아웃의 검증은 학습 효과나 향 콘텐츠의 전문적 정확성을 대신하지 않습니다.
발표에서는 유형의 차이를 이해하는지, 전체 위치를 유지하는지, 다음 시향의 질문을 갖는지 피드백을 받습니다.
